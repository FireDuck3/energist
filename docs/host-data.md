# Дані господаря

## Анкета точки (форма «Додати точку»)

15 полів, які господар заповнює при додаванні точки. Поля з * — обов'язкові (перевіряє `validateSpotForm` у `js/validate.js`).
Нові колонки — міграція `supabase/migrations/202611220001_spot_form.sql`.

| № | Поле | Обов'язковість | Де зберігається |
|---|---|---|---|
| 1 | Ім'я, прізвище, телефон, фото | * | `users.first_name/last_name`, `profiles.phone`, `profiles.avatar_path` (Storage `spot-photos/<uid>/avatar/…`) через `set_my_host_contact` |
| 2 | Назва та короткий опис СЕС | * | `pilot_spots.title`, `description` |
| 3 | Населений пункт, координати | * | `pilot_spots.district`, `lat`, `lng` (гостям до підтвердження — лише зона ~300 м) |
| 4 | Тип СЕС (мережева / автономна / гібридна) | * | `pilot_spots.ses_type` |
| 5 | Встановлена потужність СЕС | * | `pilot_spots.ses_power_kw` |
| 6 | Виробник та потужність інвертора | бажано | `pilot_spots.inverter` |
| 7 | Наявність та ємність акумулятора | * | `pilot_spots.storage_kwh` (0 — немає) |
| 8 | Наявність зарядної станції (EVSE) | * | `pilot_spots.has_evse` |
| 9 | Тип конектора | * (EVSE: Type 2 / CCS2 / CHAdeMO; без EVSE: розетка 220 В / USB) | `pilot_spots.connector` |
| 10 | Максимальна потужність заряджання | * (розетка до 22 кВт, EVSE до 150 кВт) | `pilot_spots.power_kw` |
| 11 | Тип паркування (вулиця / двір / гараж / майданчик) | * | `pilot_spots.parking_type` |
| 12 | Графік доступності | * | `opens/closes`; робочі дні — `closed_weekdays` (при створенні або кнопкою «Графік») |
| 13 | Вартість заряджання | * | `pilot_spots.price_per_kwh` |
| 14 | Фотографії об'єкта | бажано | `pilot_spots.photos` (до 5) |
| 15 | Короткий опис умов | бажано | `pilot_spots.charging_terms` |

Поля з попереднього спринту (рік встановлення, напруга, Wi-Fi, територія, чи можна залишити авто) лишилися в розділі «Додатково» форми.
Редагування: опис і характеристики — `update_pilot_spot_form` та `update_pilot_spot_details`; зміна потужності СЕС, наявності EVSE чи обладнання знімає позначку «Перевірена точка».

## Таблиця даних господаря

Що зберігаємо про господаря (власника електростанції) за підсумками спринту, де саме і хто це бачить.
Нові поля додала міграція `supabase/migrations/202611200001_host_profile_data.sql`.

Позначки: ✅ — було раніше, 🆕 — додано цією міграцією.

## Персональні та контактні дані

| Поле | Де зберігається | Хто бачить |
|---|---|---|
| Ім'я, прізвище ✅ | `users.first_name`, `users.last_name` | лише сам господар; публічно — нік `profiles.name` |
| Телефон 🆕 | `profiles.phone` (формат `+380671234567`) | господар; гість з **підтвердженим або завершеним** бронюванням цієї точки |
| Email ✅ | `users.email` | так само, як телефон |
| Дата реєстрації ✅ | `users.registered_at` | усі («на WattWay з листопада 2026») |
| Статус верифікації профілю 🆕 | `users.verified_at` | усі (позначка «✓ Перевірений господар») |

## Як це працює

- Господар заповнює опис у формі «Додати розетку» / «Редагувати» (блок «Обладнання й умови»), телефон — у профілі. Усі нові поля необов'язкові.
- Опис станції записується в `pilot_spots` (при створенні) або через `update_pilot_spot_details` (при редагуванні). Зміна року, напруги, інвертора чи акумуляторів знімає позначку «Перевірена точка».
- Сторінка точки отримує «паспорт» господаря з `pilot_spot_host_card(point_id)`: нік, дату реєстрації, верифікацію, кількість і тривалість останніх 5 завершених сесій. Телефон і email функція повертає лише самому господарю та гостю з підтвердженим або завершеним бронюванням цієї точки.

## Для адміністратора

Позначити господаря перевіреним (клієнт цього зробити не може):

```sql
update public.users set verified_at = now() where email = 'host@example.com';
```

Порядок розгортання: спершу виконати міграцію в Supabase → SQL Editor, потім деплоїти сайт. Сайт без міграції теж працює (точки додаються, профіль відкривається), але нові поля не збережуться.
