# ЕнерГість — мобільна адаптація, футер, пошук та історія

Дата: 2026-10-29
Базується на: `docs/specs/2026-10-29-energist-demo-design.md`, `docs/specs/2026-10-29-energist-auth-design.md` (ред. 2)

## 1. Мета

1. На телефоні сайт має відчуватися як застосунок: шапка не з'їдає екран, головні дії під пальцем.
2. Прибрати з футера «демо для пітчу».
3. Додати пошук точок з історією і «Мої зарядки» — обидва збережені в акаунті.

Успіх: на 360–414 px шапка в один рядок, навігація — вкладками знизу, «Забронювати» видно без прокрутки; на карті є пошук з останніми запитами й переглянутими точками; у профілі — список своїх зарядок, той самий на будь-якому пристрої.

Вхід через Google сюди не входить: він чекає, поки користувач увімкне двоетапну перевірку Google (окремий спек/зміна).

## 2. Що вирішено з користувачем

| Питання | Рішення |
|---|---|
| Футер | Прибрати «демо для пітчу»; «Скинути демо» — у профіль, дрібним посиланням |
| Історія пошуку | Поле пошуку на карті + «Нещодавні пошуки» і «Нещодавно переглянуті» |
| Де зберігати історію і зарядки | В акаунті (Supabase) |

Припущення: пошук — лише за назвою точки й районом (вулиць у даних немає); показуємо по 5 останніх записів; без входу пошук працює, але нічого не зберігає.

## 3. Мобільна адаптація (≤ 768 px)

- **Шапка** — один рядок до 60 px: логотип, перемикач блекауту лише значком (без підпису), «Увійти» або кружечок-аватар (без імені). Перемикач ролей «Я шукаю / Я ділюсь» і посилання «Калькулятор» приховані.
- **Нижня панель вкладок** (фіксована, 64 px + `env(safe-area-inset-bottom)`): 🔌 Зарядка (`#/map`, активна також на `#/spot/…`), ☀️ Господар (`#/host`), 🧮 Калькулятор (`#/calc`), 👤 Профіль (`#/profile`). Підпис під значком, активна вкладка — індиго. Сторінка має відступ знизу, щоб вміст не ховався під панеллю. На > 768 px панелі немає.
- **Головна**: спершу текст і кнопки, потім ілюстрація, висотою до 220 px.
- **Карта**: поле пошуку завжди видно; фільтри згорнуті під кнопкою «Фільтри» (з лічильником активних: «Фільтри · 2»), що розгортає їх під собою.
- **Картка точки**: картка бронювання справа прихована; замість неї — закріплена над вкладками смужка «12 грн / кВт·год» + «Забронювати» (та сама дія і ті самі правила блекауту, що й у великої кнопки).
- **Розміри**: кнопки і чипи на телефоні — не нижче 40 px.
- **Карта Leaflet** не перекриває шапку й панель вкладок при прокрутці (власний контекст накладання).
- Перевірка на 360, 375, 414, 768 і 1280 px; на > 768 px вигляд не змінюється, крім футера.

## 4. Футер і «Скинути демо»

- Футер: «ЕнерГість · Вінниця, 2026». Кнопки «Скинути демо» у футері більше немає.
- На сторінці профілю (у будь-якому стані: увійшов, не увійшов, демо-режим) унизу — дрібне посилання «Скинути демо-дані» з тією ж дією, що й раніше (скидає демо-дані, не виходить з акаунта).

## 5. Пошук та історія

### 5.1 Пошук на карті
- Поле над фільтрами: плейсхолдер «Район або назва точки», кнопка × очищає.
- Пошук без урахування регістру, апострофи `'`, `’`, `ʼ` вважаються однаковими, зайві пробіли ігноруються; збіг — входження в назву або район.
- Запит — частина фільтрів (`filters.query`), працює разом з іншими фільтрами, зберігається як і вони; «Скинути фільтри» очищає і запит.
- Порожній результат — наявний порожній стан «Нічого не знайдено» з «Скинути фільтри».

### 5.2 Підказки (при фокусі в полі)
- **Нещодавні пошуки** — до 5 останніх різних запитів (новіші зверху); клік підставляє запит; × біля запиту видаляє його; «Очистити» видаляє всі запити.
- **Нещодавно переглянуті** — до 5 останніх різних точок, які відкривав користувач; клік відкриває картку точки. Точки, яких уже немає в даних, пропускаються.
- Запит зберігається, коли натиснули Enter або обрали підказку (і запит не порожній).
- Перегляд точки зберігається при відкритті `#/spot/:id`.
- Без входу (і для `needsProfile`) підказки показують «Увійдіть, щоб зберігати історію пошуку»; нічого не зберігається. У демо-режимі історія живе лише до перезавантаження.
- Закриття підказок: клік поза полем або Esc.

### 5.3 «Мої зарядки»
- Секція на сторінці профілю (для увійденого): список зарядок, новіші зверху — точка й район, дата й час, кВт·год, сума, кнопка «Забронювати знову» (відкриває картку точки). Порожньо — «Ви ще не заряджались» + «Знайти розетку» (→ `#/map`).
- Пункт меню акаунта «Профіль» перейменовується на «Профіль і зарядки».
- Запис додається, коли бронювання увійденого (або демо) користувача оплачене й отримано > 0 кВт·год.

### 5.4 Поведінка при збоях
- Збереження в історію не блокує нічого: помилка мережі — запис лишається лише локально до перезавантаження, без повідомлень.
- Не вдалося завантажити історію — підказки й «Мої зарядки» показують порожній стан; у «Моїх зарядках» — «Не вдалося завантажити історію» + «Спробувати ще раз».

## 6. Дані (Supabase)

```sql
create table public.search_history (
  id bigint generated always as identity primary key,
  user_id uuid not null default auth.uid() references auth.users (id) on delete cascade,
  kind text not null check (kind in ('query', 'spot')),
  value text not null check (char_length(value) between 1 and 80),
  created_at timestamptz not null default now()
);
alter table public.search_history enable row level security;
create policy "own searches: read"   on public.search_history for select using (auth.uid() = user_id);
create policy "own searches: insert" on public.search_history for insert with check (auth.uid() = user_id);
create policy "own searches: delete" on public.search_history for delete using (auth.uid() = user_id);
create index search_history_user_time on public.search_history (user_id, created_at desc);

create table public.charge_history (
  id bigint generated always as identity primary key,
  user_id uuid not null default auth.uid() references auth.users (id) on delete cascade,
  spot_id text not null check (char_length(spot_id) between 1 and 80),
  spot_title text not null check (char_length(spot_title) between 1 and 120),
  district text not null default '',
  kwh numeric(8, 2) not null check (kwh > 0),
  total numeric(10, 2) not null check (total >= 0),
  charged_at timestamptz not null default now()
);
alter table public.charge_history enable row level security;
create policy "own charges: read"   on public.charge_history for select using (auth.uid() = user_id);
create policy "own charges: insert" on public.charge_history for insert with check (auth.uid() = user_id);
create index charge_history_user_time on public.charge_history (user_id, charged_at desc);
```
Зарядки з клієнта не змінюються й не видаляються. SQL дописується в `supabase/schema.sql` і виконується в SQL Editor.

## 7. Архітектура

```
js/filters.js        + normalizeQuery(s), matchSpots(spots, query); filterSpots враховує filters.query; DEFAULT_FILTERS.query = ''
js/history.js        чисті функції: recentQueries(rows, limit = 5), recentSpots(rows, spots, limit = 5)
js/user-history.js   createUserHistory(session): історія поточного користувача (кеш, запис, видалення)
js/supabase.js       + loadHistory, addSearch, removeSearch, clearSearches, addCharge
js/views/map.js      поле пошуку і підказки; мобільна кнопка «Фільтри»
js/views/spot.js     запис перегляду; мобільна смужка бронювання
js/views/booking.js  запис зарядки після оплати
js/views/profile.js  «Мої зарядки», «Очистити історію пошуку», «Скинути демо-дані»
js/app.js            нижня панель вкладок, мобільна шапка, футер без кнопки
css/styles.css       мобільні стилі
```

### 7.1 `AuthService` (доповнення)
- `loadHistory(uid) → { searches: [{ kind, value, created_at }], charges: [{ spot_id, spot_title, district, kwh, total, charged_at }] }` — по 50 останніх, новіші першими.
- `addSearch(uid, { kind, value })`, `removeSearch(uid, { kind, value })` (усі рядки з цим `kind` і `value`), `clearSearches(uid)` (лише `kind = 'query'`), `addCharge(uid, { spot_id, spot_title, district, kwh, total })`.
- Помилки — `{ code: 'auth/…' }` як у наявних методах.

### 7.2 `createUserHistory(session)`
- Стан: `{ status: 'off' | 'loading' | 'ready' | 'error' | 'local', searches, charges }`.
  - `signedIn` → `loading` → `loadHistory` → `ready` (або `error`); зміна користувача — скидання і нове завантаження.
  - `demo` → `local` (порожньо, лише в пам'яті).
  - інші стани сесії → `off` (порожньо, запис ігнорується).
- `subscribe(fn)`; `recordQuery(q)`, `recordSpot(spotId)`, `recordCharge(entry)`, `removeQuery(q)`, `clearQueries()`, `retry()`.
- Запис оптимістичний: спершу локально (новий рядок з `created_at = now`), потім у сервіс; помилка сервісу локальний запис не прибирає.
- Порожній після обрізання пробілів запит не записується; довші за 80 символів — обрізаються до 80.

## 8. Тестування

**Автотести:**
- `tests/filters.test.js`: `normalizeQuery` (регістр, апострофи, пробіли), `matchSpots` (за назвою, за районом, порожній запит — усі, «п’ятничани» знаходить «П'ятничани»), `filterSpots` з `query` разом з іншими фільтрами, `resetFilters` очищає `query`.
- `tests/history.test.js`: `recentQueries` (новіші першими, без повторів з різним регістром, ліміт 5, лише `kind = 'query'`), `recentSpots` (без повторів, ліміт, пропускає неіснуючі точки).
- `tests/user-history.test.js` (підроблені сесія і сервіс): `off` без входу і запис ігнорується; `signedIn` → `ready` з даними; оптимістичний запис з'являється одразу і йде в сервіс; помилка сервісу лишає локальний запис; `demo` → `local`; зміна користувача скидає історію; `removeQuery`/`clearQueries` прибирають локально і кличуть сервіс; порожній запит не пишеться.
- `tests/store.test.js`: `resetFilters` скидає `query`.

**Правила доступу (Claude, без входу):** анонімний `POST` у `search_history` і `charge_history` з publishable-ключем відхиляється; анонімний `GET` повертає `[]`.

**У браузері (Claude):** 360 / 375 / 414 / 768 / 1280 px на всіх екранах — немає горизонтального скролу, шапка ≤ 60 px на мобільному, вкладки працюють і підсвічують активну, смужка бронювання видима на картці точки, фільтри згортаються; пошук і підказки з підробленою сесією (`ready`, `off`, `local`); «Мої зарядки» з даними і порожні; футер без «демо для пітчу»; консоль без помилок.

**Справжня перевірка (користувач, на живому сайті):** пошук → запит з'являється в «Нещодавніх» на іншому пристрої/браузері після входу; відкрита точка — у «Нещодавно переглянутих»; зарядка → запис у «Моїх зарядках». Claude перевіряє в Supabase Table Editor, що рядки належать користувачу.

## 9. Поза рамками
Вхід через Google (чекає 2SV користувача), пошук за вулицями/адресою, синхронізація демо-бронювань між пристроями, видалення окремих зарядок, експорт історії.
