# Етап 1: реальні публічні зарядні станції — дизайн

## Мета
Показати на карті справжні публічні станції для електромобілів (спочатку Вінниця й область) окремо від приватних точок WattWay і демо-точок, чесно позначивши, що про них відомо, а що ні.

## Цілі
- Щоденний імпорт з Open Charge Map (OCM) та OpenStreetMap (Overpass) у таблицю `public_charging_stations`.
- Без дублів між джерелами.
- На карті три види маркерів: приватні (WattWay), публічні (оператори), демо (лише в деморежимі).
- Картка станції: назва, адреса, оператор, потужність, роз'єми, графік/доступ (якщо відомі), джерело, дата оновлення, авторство.
- «Прокласти маршрут»; «Відкрити в застосунку оператора» лише за відомого офіційного посилання.
- Статус завжди «Статус невідомий» (офіційних інтеграцій немає). Ціна лише з перевірених даних, інакше не показується.
- Бронювання сторонніх станцій недоступне.

## Не цілі Етапу 1
Геолокація, радіус, фільтри за роз'ємом/потужністю, кластеризація (Етап 2). Скарги користувачів на станції (Етап 4). Адмін-редагування каталогу (Етап 5).

## Підходи
1. **GitHub Actions + Node-скрипт (обрано користувачем).** Щоденний cron, `service_role` у GitHub Secrets, upsert у Supabase через REST. Плюси: без Supabase CLI, є прецедент (`keepalive.yml`), легко тестувати скрипт локально. Мінус: лог у GitHub, а не в Supabase.
2. Supabase Edge Function + pg_cron. Потребує CLI й окремого розгортання; відкинуто.

## Дизайн
**Таблиця `public_charging_stations`:** `id uuid`, `source text` (`ocm`|`osm`|`merged`), `external_id text`, `unique(source, external_id)`, `name`, `address`, `operator`, `lat`, `lng`, `max_power_kw numeric`, `connectors jsonb` (`[{type, power_kw, count}]`, нормалізовані типи: type2, ccs2, chademo, gbt, tesla, other), `price_per_kwh numeric null`, `price_verified bool`, `opening_hours text null`, `access text null`, `operator_url text null`, `status text default 'unknown'`, `sources jsonb` (список джерел зі своїми id та посиланнями на ліцензію/авторство), `updated_at`, `source_updated_at`, `is_active bool`. Індекс GiST/або btree по (lat,lng) + `earthdistance`/простий bbox-індекс.
**RLS:** `select` для всіх (лише `is_active`), insert/update/delete — ніхто з клієнта; пише лише `service_role` з Actions.
**Таблиця `station_sync_runs`:** час, джерело, кількість отриманих/вставлених/оновлених/пропущених, помилка (для Етапу 5). RLS: без доступу клієнтам.
**Синхронізація (`scripts/sync-stations/`):** fetch OCM (потрібен `OCM_API_KEY`, bbox області) та Overpass (`amenity=charging_station`), нормалізація до однієї моделі, дедуплікація (відстань < 60 м і схожа назва/оператор — зливаємо в один запис, зберігаючи обидва джерела), upsert. Недоступність API: повторні спроби з паузою, при повній відмові джерела його записи не чіпаємо (не деактивуємо), run позначається помилкою. Станції, що зникли з обох джерел кілька запусків поспіль, ставляться `is_active=false`.
**Workflow:** `.github/workflows/sync-stations.yml`, cron раз на добу + `workflow_dispatch`.
**Фронтенд:** `js/stations.js` (завантаження з Supabase через anon-ключ + кеш у `sessionStorage` на кілька годин, нормалізація для карти), окремий тип маркера у `js/views/map.js`, картка/popup станції без кнопки бронювання. Демо-точки показуються лише з прапором деморежиму; реальні й демо не змішуються в одному списку без позначки.
**Ліцензії:** OCM — CC BY 4.0 (авторство), OSM — ODbL (© OpenStreetMap contributors). Рядок авторства в картці й у футері карти.
**Тести:** нормалізація, дедуплікація, злиття, логіка графіка й ціни — юніт-тести на Node без мережі (фікстури відповідей).

## Залишено на виконавця / мої рішення
- Межі «Вінницької області» — обмежувальний прямокутник (мій вибір для старту, потім розширення на Україну).
- Деморежим: проста перемикач-прапорець у `store`, за замовчуванням вимкнений для публічної карти (мій вибір).

## Потрібно від користувача
Ключ OCM, секрети `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, `OCM_API_KEY` у репозиторії, застосування міграції в Supabase SQL Editor.
