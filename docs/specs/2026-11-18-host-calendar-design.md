# Етап 3: календар доступності, редагування точок, фотографії — дизайн

## Мета
Господар керує своєю точкою сам (графік, вихідні, пауза, характеристики, фото), а гість бронює на будь-який із найближчих 30 днів і бачить лише справді вільний час.

## Що вже є (не дублюємо)
- `pilot_spots` (Supabase): назва, район, координати, джерело, роз'єм, потужність, ціна, пристрої, `opens/closes`, `archived_at`; публікація й архівування господарем.
- `pilot_bookings` з GiST-обмеженням `exclude (spot_id =, slot &&)` для `pending/confirmed` — подвійне бронювання вже неможливе на рівні БД.
- `request_pilot_booking` дозволяє лише сьогодні/завтра (`requested_day <= today + 1`), 1–6 год, у межах `opens/closes`.
- Модалка бронювання (`js/views/booking.js`) — вибір «Сьогодні / Завтра».

## Цілі
1. **Календар на 30 днів:** гість обирає дату з 30 днів уперед; зайняті години, вихідні, неробочі дні тижня й пауза позначені й недоступні.
2. **Графік господаря:** робочі години (`opens/closes`), неробочі дні тижня, окремі вихідні дати.
3. **Пауза:** господар тимчасово вимикає точку — її не видно на карті для нових бронювань, наявні бронювання лишаються.
4. **Редагування точки:** назва, район, координати, роз'єм, потужність, ціна, пристрої, години.
5. **Фото:** до 5 фото на точку (JPEG/PNG/WebP, до 2 МБ), перше — обкладинка; видалення.
6. Усі обмеження перевіряються на сервері (RPC/RLS), не лише в інтерфейсі.

## Не цілі (наступні етапи)
Скасування з причиною, «Не з'явився гість»/«Господар не надав доступ», підтвердження початку/завершення, статистика й перегляди, приховування від пошуку окремо від паузи, правила користування й спосіб зв'язку, кабінет гостя.

## Підходи
1. **Розширити наявні таблиці й RPC (обрано).** Нові колонки в `pilot_spots`, таблиця вихідних, оновлений `request_pilot_booking`, RPC доступності без персональних даних, Supabase Storage для фото. Плюс: тримається поточної архітектури й гарантій БД.
2. Окрема таблиця «слотів» з наперед згенерованими годинами — дублює GiST-захист, ускладнює редагування графіка; відкинуто.
3. Фото як base64 у таблиці — роздуває рядки й відповіді карти; відкинуто.

## Дизайн
**Міграція** `supabase/migrations/202611180002_host_calendar.sql`:
- `pilot_spots`: `paused boolean not null default false`, `closed_weekdays smallint[] not null default '{}'` (1 = пн … 7 = нд, ISO), `photos text[] not null default '{}'` (шляхи в Storage, до 5).
- `pilot_spot_days_off(spot_id uuid references pilot_spots, day date, primary key(spot_id, day))`, RLS: читати всім, писати лише власнику точки.
- `update_pilot_spot(point_id, …поля)` — security definer, лише власник, ті самі перевірки, що й при створенні; зміни не скасовують наявних бронювань.
- `set_pilot_spot_paused(point_id, paused)`, `set_pilot_spot_days_off(point_id, days date[])` (замінює список у межах наступних 60 днів), `set_pilot_spot_photos(point_id, paths text[])` (≤5, лише шляхи з префіксом `<owner_id>/<point_id>/`).
- `pilot_spot_availability(point_id, from_day, to_day)` — security definer, повертає лише зайняті інтервали (`tsrange`) `pending/confirmed`, без гостя й статусу, плюс вихідні; максимум 31 день.
- `request_pilot_booking`: межа `requested_day <= today + 29`, відмова для `paused`, архівованої точки, `closed_weekdays`, днів у `pilot_spot_days_off`.
- Storage: публічний бакет `spot-photos` (читання всім), запис/видалення лише в теці `<auth.uid()>/…`; ліміт 2 МБ і MIME `image/jpeg|png|webp` на бакеті.
- Карта (`listPilotSpots`) не показує точки на паузі для інших; власник бачить свою з позначкою «На паузі».

**Фронтенд:**
- `js/calendar.js` (чисті функції): `calendarDays(today, n = 30)`, `dayStatus(day, spot, availability, now)` → `open | closed | dayoff | paused | full | past`, `freeStarts(day, spot, busy, now)` — початкові години без перетину із зайнятими інтервалами з урахуванням тривалості.
- `js/views/booking.js`: замість «Сьогодні/Завтра» — смуга з 30 днів (для пілотних точок) зі станами з `dayStatus`; слоти з `freeStarts`; демо-точки працюють як раніше.
- `js/views/host.js`: для кожної власної точки — «Редагувати» (форма з наявними перевірками `validate.js`), «Графік» (години, дні тижня, вихідні в календарі на 60 днів), «На паузу / Увімкнути», «Фото» (завантаження з попереднім переглядом, видалення, обкладинка).
- `js/supabase.js`: нові методи сервісу для RPC і Storage (`uploadSpotPhoto`, `removeSpotPhoto`).
- Картка точки й карта показують першу фотографію, якщо є (інакше нинішня обкладинка).

**Тести:** `tests/calendar.test.js` (межі 30 днів, вихідні, дні тижня, пауза, перетин з бронюваннями, минулі години сьогодні, часовий пояс Києва для «сьогодні»), тести валідації фото (тип, розмір, ліміт 5) і методів сервісу з підробленим клієнтом. SQL перевіряється вручну за чеклістом у README (немає локального Postgres).

## Рішення, ухвалені мною
- Пауза ховає точку з карти для всіх, крім власника; наявні бронювання не скасовуються.
- Зміна ціни чи годин не впливає на вже створені бронювання.
- Вихідні редагуються на 60 днів уперед; календар гостя — 30 днів.
- Фото стискаються в браузері до ширини 1600 px перед завантаженням (менше трафіку й місця в безкоштовному Storage).
