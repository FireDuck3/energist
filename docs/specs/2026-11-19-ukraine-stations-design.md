# Станції по всій Україні без «зависання» сайту — дизайн

## Мета
Показувати всі публічні зарядні станції України (орієнтовно 5–8 тис.) так, щоб карта відкривалася швидко й на телефоні, а фільтри, радіус і «Знайти найближчу» працювали по всій країні.

## Як зараз
- Синхронізація (`scripts/sync-stations`, GitHub Actions щоночі) бере лише прямокутник Вінницької області (`BBOX`), 74 станції.
- Сайт (`js/stations.js`) одним запитом читає з таблиці всі поля всіх станцій (~750 байт на станцію), кеш у `sessionStorage` на 3 год.
- Обмеження: PostgREST віддає максимум 1000 рядків за запит (і сайт, і `listActive` у синхронізації мовчки обрізаються); пошук дублів порівнює кожну станцію з кожною.

## Обраний підхід (А): стислий файл-знімок
Синхронізація після запису в таблицю будує компактний файл зі станціями й кладе його в публічне сховище Supabase (CDN). Сайт завантажує лише цей файл, а повні дані станції — при відкритті її картки.

Відкинуто: Б — завантаження за видимою частиною карти (потребує серверних запитів для «найближчої», пошуку й групування на віддаленому масштабі); В — повна таблиця з пагінацією (4–6 МБ на старті).

## Цілі
1. Синхронізація всієї України: OCM за `countrycode=UA` без прямокутника; Overpass по території країни (`area["ISO3166-1"="UA"][admin_level=2]`, тайм-аут 180 с, повтори як зараз).
2. Пошук дублів за сіткою (~100 м клітинки, перевірка лише сусідніх клітинок) — лінійний час, ті самі правила злиття.
3. `listActive` у синхронізації читає таблицю посторінково (по 1000), щоб деактивація бачила всі рядки.
4. Знімок `stations-v1.json` у публічному бакеті `public-data` (оновлюється щоночі, `Cache-Control: max-age=3600`):
   ```
   { "v": 1, "generated_at": "...", "count": N,
     "rows": [[id, lat, lng, maxPowerKw|null, connMask, flags, priceUah|null, "Назва"], ...] }
   ```
   `connMask`: type2=1, ccs2=2, chademo=4, gbt=8, інші=16. `flags`: цілодобово=1, ціна перевірена=2. Координати округлено до 5 знаків. Очікуваний розмір ~1 МБ, стиснутий ~250–300 КБ.
5. Сайт: `loadPublicStations` читає знімок (кеш у пам'яті на сесію + звичайний HTTP-кеш браузера), розгортає його в легкі об'єкти, сумісні з наявними фільтрами (`matchStation`, `stationConnectors`, `sortByDistance`).
6. Повна картка станції (адреса, оператор, роз'єми з потужністю, графік, доступ, джерела, дата оновлення, посилання оператора) довантажується з таблиці за `id` при відкритті popup/картки; поки вантажиться — «Завантаження…»; при збої — коротка картка з тим, що є в знімку, і кнопка «Прокласти маршрут».
7. Карта: маркери станцій у кластерах з `chunkedLoading` (додаються порціями, без підвисання); перебудова лише коли змінились фільтри, а не на кожне оновлення стану.
8. Список зліва: не більше 50 станцій — найближчі до мого місця або до центру карти, серед відфільтрованих; підпис «Показано 50 найближчих із N». Лічильник «Знайдено … публічних станцій» — по всій країні.
9. Карта на старті — як зараз (центр Вінниці), без автопідгону під усю країну.

## Не цілі
Статуси в реальному часі, офіційні API операторів, серверне групування маркерів, офлайн-режим.

## Рішення, ухвалені мною
- Знімок замість таблиці для карти; таблиця лишається джерелом правди (скарги, деталі, адмінка).
- Бакет `public-data` створюється міграцією; писати в нього може лише `service_role` (синхронізація).
- Якщо знімок недоступний (перший запуск, збій) — сайт тихо падає на старий шлях: читання таблиці посторінково, але не більше 2000 станцій, щоб не зависнути.
- Перший запуск на всю Україну робимо вручну (Run workflow) і перевіряємо кількість, розмір файлу й швидкість карти на телефоні.

## Перевірка
Юніт-тести: формат і розгортання знімка, сітковий пошук дублів (ті самі результати, що й старий, на фікстурах + 5 000 випадкових точок за < 1 с), пагінація `listActive`, вибір 50 найближчих. Ручна: розмір знімка, час відкриття карти, плавність на телефоні (375 px), фільтри по всій країні.
