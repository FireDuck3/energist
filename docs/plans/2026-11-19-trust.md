# Рейтинги, скарги, «Перевірена точка» (Етап 4б) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Рейтинг господаря й «Нова точка», скарги на точки/станції/користувачів із перевірками на сервері, позначка «Перевірена точка», яку ставить лише адміністратор.

**Architecture:** Міграція додає `pilot_spots.verified_at` (скидання при зміні адреси/обладнання) і таблицю `reports` з RPC `submit_report`. Чисті функції в `js/trust.js`; модалка скарги `js/views/report.js`; вбудовування в сторінку точки, карту й чат.

**Tech Stack:** HTML/CSS/JS, Supabase (Postgres, RLS, RPC).

**Spec:** `docs/specs/2026-11-18-trust-design.md`

## Global Constraints

- Тести: `py tests/serve.py 8420` (запустити у фоні, якщо не працює), `bash tests/run-headless.sh`; база 208/208; `revealOnScroll` — відомий нестабільний тест.
- Типи цілей: `spot`, `station`, `user`. Причини (id → текст):
  - spot: `wrong_address` «Неправильна адреса», `wrong_equipment` «Неправильне обладнання», `not_working` «Не працює», `unsafe` «Небезпечно», `fraud` «Шахрайство», `other` «Інше».
  - station: `wrong_address`, `wrong_equipment`, `not_working` «Не працює або закрита», `other`.
  - user: `fraud` «Шахрайство», `abuse` «Образи», `spam` «Спам», `no_show` «Не з'явився або не надав доступ», `other` «Інше».
- Опис до 1000 символів; для `other` опис обов'язковий (≥ 10 символів).
- Ліміти на сервері: 10 скарг на добу від автора; одна відкрита скарга автора на ту саму ціль; не на власну точку; на користувача — лише співрозмовник у спільному бронюванні.
- Тексти: «★ 4,8 · 12 відгуків», «Нова точка», «Новий господар», «✓ Перевірена точка» з поясненням «WattWay перевірив точку на місці».
- Коміти з `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

- Повторна скарга на ту саму ціль або 11-та за добу → зрозуміле повідомлення в модалці, а не загальна помилка (Task 1 SQL-коди + Task 3 відображення).
- Скарга з чату на співрозмовника, коли бронювання скасоване — дозволена (спільне бронювання існувало) (Task 1).
- Господар бачить свою точку — кнопки «Повідомити про проблему» немає (Task 3).
- Точка без відгуків і господар без відгуків — «Нова точка» / «Новий господар», без NaN (Task 2).
- Зміна лише ціни чи назви не знімає позначку «Перевірена» (Task 1).

**Interfaces:**
- Produces: `pilot_spots.verified_at timestamptz`; `create or replace update_pilot_spot` (та сама сигнатура) з `verified_at = case when lat/lng/connector/power_kw змінились then null else verified_at end`; таблиця `reports(id uuid pk, reporter_id uuid not null references auth.users, target_type text check in ('spot','station','user'), target_id text not null, booking_id uuid null references pilot_bookings, reason text not null, details text not null default '' check length ≤ 1000, status text not null default 'open' check in ('open','resolved','rejected'), created_at, resolved_at, resolution text)`; частковий унікальний індекс `(reporter_id, target_type, target_id) where status = 'open'`; RLS: `select` лише свої; запису напряму немає; `submit_report(target_type text, target_id text, reason text, details text, booking_id uuid default null) returns uuid` (security definer) з помилками: `42501` (не увійшов/неактивний), `22023` + повідомлення `bad_reason` / `bad_target` / `own_spot`, `WW429` + `daily_limit`, `23505` + `duplicate`.

- [ ] **Step 1:** Написати міграцію за стилем попередніх. Перевірка цілі: `spot` — існує в `pilot_spots`, не архівована, `owner_id <> auth.uid()` (інакше `own_spot`); `station` — `public_charging_stations.id::text = target_id and is_active`; `user` — `booking_id` не null, автор і `target_id` — дві різні сторони цього бронювання (`guest_id`/`owner_id` через `pilot_spots`). Для `other` — `length(btrim(details)) >= 10`. Ліміт — `pg_advisory_xact_lock` на автора + count за добу.
- [ ] **Step 2:** README: застосування й чекліст (дубль → `duplicate`; 11-та за добу → `daily_limit`; на власну точку → `own_spot`; на користувача без спільного бронювання → `bad_target`; зміна ціни не знімає `verified_at`, зміна координат знімає; інший користувач не бачить чужих скарг; як вручну позначити точку перевіреною SQL-запитом).
