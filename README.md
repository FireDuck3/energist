# ЕнерГість — демо для пітчу

P2P-маркетплейс електрики («енергетичний Airbnb»): гість знаходить розетку на карті Вінниці, бронює час,
заряджається і платить за фактичні кВт·год; господар із СЕС чи батареєю заробляє на надлишку.

Це клікабельне демо: точки, бронювання й оплата вигадані і зберігаються лише у вашому браузері. Справжні тільки акаунти (Supabase): реєстрація, вхід і профіль з ім'ям та роллю.

Сайт: https://energist.onrender.com

## Запуск локально

Потрібен лише Python (ES-модулі не працюють, якщо відкрити `index.html` подвійним кліком).

```bash
py tests/serve.py 8420
```

Далі відкрийте http://localhost:8420/ — тести: http://localhost:8420/tests/

## Сценарій пітчу (3–5 хв)

1. **Головна** — проблема Саші й Олега, «Як це працює», калькулятор.
2. **«Я шукаю зарядку»** — карта Вінниці, фільтр «Електромобіль».
3. **⚡ Блекаут** — карта темніє, лишаються лише точки з СЕС і батареями.
4. **«Сонячний дах Олега» → Забронювати** — час → заморожування грошей → зарядка (20 с) → оплата з комісією → відгук.
5. **«Я ділюсь енергією»** — бронювання Саші вже в кабінеті Олега, заробіток зріс; «Додати розетку» — і вона одразу на карті.
6. **«Скинути демо»** (внизу сторінки) — повертає все до початкового стану перед наступним показом.

## Де що міняти

| Що | Де |
|---|---|
| Комісія, тарифи, ціни, точки, відгуки, господарі | `js/data.js` |
| Уся грошова математика | `js/pricing.js` |
| Кольори й вигляд | `css/styles.css` (змінні на початку файлу) |

Після зміни засіяних даних у `js/data.js` збільште `DATA_VERSION` — тоді збережений у браузерах старий стан демо скинеться сам.

## Акаунти (Supabase)

- Проєкт Supabase `energist`; публічні адреса і ключ — у `js/supabase-config.js` (їх можна викладати: доступ до даних обмежують правила RLS).
- Таблиця профілів і правила — `supabase/schema.sql` (виконується в Supabase → SQL Editor).
- Увесь код, що говорить із Supabase, — у `js/supabase.js`; логіка сесії — у `js/auth.js` (тести в `tests/auth.test.js`).
- Підтвердження пошти вимкнено: реєстрація паролем миттєва.
- **Вхід кодом з пошти і «Забули пароль?»** вимкнені (`emailCodes: false`), бо вбудована пошта Supabase не дає змінити шаблони листів. Щоб увімкнути: підключити власний SMTP (напр., Brevo) у Authentication → Emails → SMTP Settings; у шаблонах «Magic link or OTP» і «Reset password» написати текст з `{{ .Token }}` (без посилань); поставити `emailCodes: true`.
- Безкоштовний проєкт засинає після тижня без запитів — щодня його «будить» `.github/workflows/keepalive.yml`.
- Без інтернету вікно входу пропонує «Продовжити в демо-режимі».

## Хостинг (Render)

Static Site на Render з публічного репозиторію `FireDuck3/energist`, гілка `main`, без збірки, папка — корінь. Автодеплою немає: після пушу натисніть у Render **Manual Deploy → Deploy latest commit**. Власний домен — Settings → Custom Domains.

Карта — тайли OpenStreetMap, тож на пітчі потрібен інтернет. Без нього список точок і всі сценарії працюють, замість карти буде підказка.

## Структура

```
index.html            каркас
css/styles.css        стилі, світла тема і тема блекауту
js/app.js             вхід: store, сесія, шапка, маршрути
js/data.js            константи й засіяні дані
js/pricing.js         розрахунки грошей
js/filters.js         фільтри точок і слоти бронювання
js/validate.js        перевірка форми «Додати розетку»
js/stats.js           зведення для кабінету господаря
js/store.js           стан + збереження в localStorage
js/auth.js            сесія і вхід (без залежності від сервісу)
js/supabase.js        адаптер Supabase
js/supabase-config.js публічний конфіг Supabase
js/router.js          хеш-маршрути (#/, #/map, #/spot/:id, #/host, #/calc, #/profile)
js/views/*.js         екрани
tests/                тести в браузері + dev-сервер
supabase/schema.sql   таблиця профілів і правила доступу
docs/                 спеки і плани
```
